## Why

Когда в Qwen Code запускается `/opsx-explore` или `/opsx-propose`, ход OpenSpec-флоу виден только по ленте вызовов инструментов. Непонятно, на каком шаге флоу находится агент, какой артефакт он сейчас пишет, ответа от какого MCP-сервера ждёт. Момента, где пользователь осознанно принимает артефакт, тоже нет: в режимах auto-edit/YOLO артефакты записываются молча. В Qwen Code 0.25.2 появились всё нужное, чтобы решить это без форка: расширения с хуками (`PreToolUse`, `PermissionRequest`, `UserPromptExpansion` и др.), status line с командой и принудительный диалог подтверждения через `permissionDecision: "ask"`.

## What Changes

- Новое расширение Qwen Code `qwen-opsx-ui`. Оно ставится через `qwen extensions link/install` и состоит из одного Node-скрипта без зависимостей, хуков в манифесте и короткого `QWEN.md`.
- **Трекинг сессии**: хуки расширения записывают события OpenSpec-флоу текущей сессии Qwen. Это запуск `opsx-*` команд и скиллов, активный change, артефакт в работе, вызовы MCP в ожидании ответа и решения по подтверждению.
- **Компактный UI в сессии**: status line Qwen в футере, до 2 строк. Строка 1: шаг флоу (explore → propose → apply → archive) и активный change. Строка 2: статусы артефактов, текущий артефакт и ожидаемые MCP с таймером. Вне OpenSpec-флоу показывается компактная строка по умолчанию либо прежний status line пользователя.
- **Подтверждение артефактов**: запись или правка планировочного артефакта активного change (`openspec/changes/<change>/…`) через `write_file`/`edit` всегда вызывает нативный диалог Qwen approve/deny, в любом режиме одобрения. Отказ отражается в UI, а агенту сообщается причина.
- **Команда установки** `opsx-ui setup`: прописывает status line в настройки Qwen проекта или пользователя. Чужой status line без явного флага не перезаписывается. Команда также проверяет, что OpenSpec-команды для Qwen установлены.
- Существующий код не меняется (проект новый), **BREAKING**-изменений нет.

## Capabilities

### New Capabilities
- `qwen-opsx-ui/session-tracking`: распознавание OpenSpec-флоу в сессии Qwen по событиям хуков. Сюда входят фаза флоу, активный change, текущий артефакт, вызовы MCP в ожидании ответа, изоляция по сессиям и хранение состояния.
- `qwen-opsx-ui/status-line`: рендер компактного двухстрочного UI в футере Qwen по состоянию сессии и артефактов: шаг флоу, change, статусы артефактов, ожидание MCP и подтверждения, поведение вне флоу.
- `qwen-opsx-ui/artifact-approval`: обязательное подтверждение пользователем записи и правки планировочных артефактов. Сюда входят исключения (фаза apply), настройка режима гейта, поведение при отказе.
- `qwen-opsx-ui/extension-setup`: упаковка в виде расширения Qwen Code и команда установки status line с сохранением существующей конфигурации пользователя.

## Impact

- **Новый код**: корень репозитория `openspec-ui` становится расширением Qwen Code (`qwen-extension.json`, `QWEN.md`, `bin/opsx-ui.mjs`, `src/**`, тесты на `node --test`). Сборка не нужна, рантайм-зависимостей нет, нужен Node ≥ 20.
- **Внешние системы**: Qwen Code ≥ 0.25.2 (хуки расширений, `ui.statusLine` типа `command`, `permissionDecision: "ask"`), OpenSpec CLI ≥ 1.13 (`openspec status --json` и сгенерированные `openspec init --tools qwen` файлы `.qwen/commands/opsx-*.md`).
- **Пользовательские настройки**: `opsx-ui setup` меняет `ui.statusLine` в `.qwen/settings.json` проекта (или `~/.qwen/settings.json` с `--user`).
- **Файлы состояния**: журналы событий сессий в `~/.qwen/opsx-ui/sessions/`, вне репозитория пользователя. Старые журналы чистятся автоматически.
- **Производительность**: каждый вызов хука запускает процесс Node (порядка 50 мс) только для подходящих инструментов. Status line обновляется раз в секунду и читает только локальные файлы.
- **Ограничения**: Qwen 0.25 не даёт расширениям API для собственных панелей, поэтому UI ограничен двумя строками футера и нативными диалогами. Qwen-«моды» (`experimental.mods`) работают только в неинтерактивном режиме и не используются.
