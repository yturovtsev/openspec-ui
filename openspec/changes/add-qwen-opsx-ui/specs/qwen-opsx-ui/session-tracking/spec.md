## Purpose

Распознаёт ход OpenSpec-флоу внутри конкретной сессии Qwen Code по событиям хуков: шаг флоу, активный change, артефакт в работе и вызовы MCP в ожидании ответа. Это состояние нужно UI и гейту подтверждения.

## ADDED Requirements

### Requirement: Распознавание фазы флоу
Расширение SHALL определять текущую фазу OpenSpec-флоу сессии по запуску OpenSpec-команд и скиллов: `explore`, `propose`, `update`, `apply`, `sync`, `archive`. Источник — слэш-команда `opsx-<фаза>` или вызов скилла `openspec-<действие>` (`openspec-explore`, `openspec-propose`, `openspec-update-change`, `openspec-apply-change`, `openspec-sync-specs`, `openspec-archive-change`). Каждый новый запуск MUST заменять предыдущую фазу сессии.

#### Scenario: Запуск слэш-команды
- **WHEN** пользователь отправляет в Qwen `/opsx-propose добавить авторизацию`
- **THEN** фаза сессии становится `propose`

#### Scenario: Запуск через скилл
- **WHEN** агент вызывает инструмент `skill` со скиллом `openspec-explore`
- **THEN** фаза сессии становится `explore`

#### Scenario: Смена фазы
- **WHEN** в сессии с фазой `propose` пользователь запускает `/opsx-apply`
- **THEN** фаза сессии становится `apply`

#### Scenario: Посторонняя команда
- **WHEN** пользователь запускает слэш-команду, не относящуюся к OpenSpec (например, `/review`)
- **THEN** фаза сессии не меняется

### Requirement: Определение активного change
Расширение SHALL считать активным change сессии последний change, на который сослался агент. Источники: shell-команда `openspec new change "<name>"`, shell-команда `openspec <подкоманда> … --change "<name>"`, запись или правка файла по пути `openspec/changes/<name>/…`. Пути внутри `openspec/changes/archive/` MUST NOT делать change активным.

#### Scenario: Создание change
- **WHEN** агент выполняет `openspec new change "add-auth"`
- **THEN** активным change сессии становится `add-auth`

#### Scenario: Ссылка через --change
- **WHEN** агент выполняет `openspec status --change "fix-login" --json`
- **THEN** активным change сессии становится `fix-login`

#### Scenario: Архивный путь
- **WHEN** агент читает или пишет файл в `openspec/changes/archive/2026-01-01-old/`
- **THEN** активный change сессии не меняется

### Requirement: Определение артефакта в работе
Расширение SHALL считать артефакт в работе (current artifact) по последнему из событий: выполнение `openspec instructions <artifact-id> --change "<name>"` или попытка записи файла, который относится к артефакту активного change. Когда фаза меняется или артефакт записан и подтверждён, текущий артефакт MUST сбрасываться.

#### Scenario: Агент запросил инструкции
- **WHEN** агент выполняет `openspec instructions design --change "add-auth" --json`
- **THEN** текущим артефактом сессии становится `design` в состоянии «пишется»

#### Scenario: Артефакт записан
- **WHEN** запись `openspec/changes/add-auth/design.md` подтверждена и выполнена
- **THEN** текущий артефакт сессии сбрасывается, а `design` отмечается как записанный в этой сессии

### Requirement: Отслеживание вызовов MCP
Расширение SHALL фиксировать каждый вызов MCP-инструмента (имя вида `mcp__<server>__<tool>`) от начала до завершения: сервер, инструмент, время начала. Вызов, для которого показан диалог разрешения, MUST помечаться как ожидающий подтверждения пользователя. Успешное или неуспешное завершение вызова MUST снимать его из ожидающих и сохранять длительность. Все оставшиеся вызовы MUST сниматься в трёх случаях: ход агента закончился (событие `Stop`), ход отменён и Qwen вернулся к ожиданию ввода, пользователь отправил новый запрос. Конец сессии тоже MUST их снимать.

#### Scenario: Вызов в процессе
- **WHEN** агент вызывает `mcp__context7__get-library-docs` и ответа ещё нет
- **THEN** состояние сессии содержит ожидающий вызов сервера `context7`, инструмента `get-library-docs` и время его начала

#### Scenario: Вызов ждёт разрешения
- **WHEN** для вызова MCP-инструмента Qwen показал диалог разрешения
- **THEN** этот вызов помечается как ожидающий подтверждения пользователя, а не ответа сервера

#### Scenario: Вызов завершился ошибкой
- **WHEN** вызов MCP-инструмента завершился ошибкой или таймаутом
- **THEN** вызов снимается из ожидающих

#### Scenario: Ход завершён
- **WHEN** пришло событие `Stop`, а вызов MCP ещё числится ожидающим
- **THEN** вызов снимается из ожидающих

#### Scenario: Ход отменён
- **WHEN** пользователь отменил ход (Esc или отказ в диалоге), Qwen вернулся к ожиданию ввода, а вызов MCP ещё числится ожидающим
- **THEN** вызов снимается из ожидающих

### Requirement: Изоляция по сессиям
Состояние флоу (фаза, активный change, текущий артефакт, вызовы MCP) SHALL храниться отдельно для каждой сессии Qwen по её `session_id`. Две одновременные сессии в одном проекте MUST NOT видеть фазу, артефакт в работе и вызовы MCP друг друга. Возобновлённая сессия (`--resume`/`--continue`) с тем же `session_id` MUST продолжать своё сохранённое состояние.

#### Scenario: Две сессии
- **WHEN** в сессии A идёт `/opsx-propose`, а в сессии B того же проекта — `/opsx-explore`
- **THEN** сессия A видит фазу `propose`, сессия B — фазу `explore`

#### Scenario: Возобновление
- **WHEN** пользователь возобновляет сессию с фазой `propose` и активным change `add-auth`
- **THEN** UI сразу показывает фазу `propose` и change `add-auth`

### Requirement: Безвредность для работы Qwen
Обработчики хуков трекинга SHALL NOT блокировать, задерживать или изменять вызовы инструментов, кроме случаев, описанных в `qwen-opsx-ui/artifact-approval`. Любая внутренняя ошибка трекинга MUST приводить к нейтральному ответу хука: без решения и без сообщения пользователю. Ошибку MUST записывать в отладочный журнал расширения. Хуки MUST срабатывать только на инструменты и события, нужные для трекинга.

#### Scenario: Повреждённый файл состояния
- **WHEN** файл состояния сессии повреждён или недоступен на запись
- **THEN** вызов инструмента выполняется так же, как без расширения, а ошибка попадает в отладочный журнал

#### Scenario: Нерелевантный инструмент
- **WHEN** агент вызывает `read_file` или `grep_search`
- **THEN** хук трекинга расширения для этого вызова не запускается

### Requirement: Приватность и очистка состояния
Состояние сессий SHALL храниться вне репозитория пользователя, в каталоге данных Qwen пользователя. В него MUST NOT попадать текст промптов, содержимое файлов и ответы MCP-инструментов. Сохраняются только имя команды, имя change, идентификаторы артефактов, пути внутри OpenSpec-каталогов, имена MCP-серверов и инструментов, метки времени и решения по подтверждению. Состояние сессий старше 7 дней MUST удаляться при старте новой сессии.

#### Scenario: Аргументы команды не сохраняются
- **WHEN** пользователь запускает `/opsx-propose` с описанием задачи
- **THEN** в состоянии сессии есть фаза `propose`, но нет текста описания

#### Scenario: Очистка старых сессий
- **WHEN** стартует новая сессия Qwen, а состоянию другой сессии больше 7 дней
- **THEN** устаревшее состояние удаляется
