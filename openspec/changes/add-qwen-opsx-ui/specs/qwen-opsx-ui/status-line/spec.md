## Purpose

Показывает компактный UI OpenSpec-флоу в футере Qwen Code (status line, до двух строк). Видно шаг флоу, активный change, статусы артефактов и то, чего агент ждёт сейчас: ответа MCP или подтверждения пользователя.

## ADDED Requirements

### Requirement: Двухстрочный вид активного флоу
Когда в сессии есть фаза OpenSpec-флоу, status line SHALL выводить ровно две строки.

Строка 1 — шаги `explore → propose → apply → archive` с выделенным текущим шагом и имя активного change, если он есть. Фаза `update` MUST отображаться как шаг `propose` с пометкой `update`, фаза `sync` — как шаг `archive` с пометкой `sync`.

Строка 2 — статусы артефактов активного change и текущая активность. Status line MUST NOT выводить больше двух строк ни в каком состоянии.

#### Scenario: Идёт propose
- **WHEN** фаза сессии `propose`, активный change `add-auth`, `proposal` и `specs` готовы, агент пишет `design`
- **THEN** строка 1 выделяет шаг `propose` и показывает `add-auth`, строка 2 показывает `proposal` и `specs` готовыми, `design` в работе, `tasks` не начатым

#### Scenario: Фаза update
- **WHEN** фаза сессии `update`
- **THEN** строка 1 выделяет шаг `propose` с пометкой `update`

### Requirement: Статусы артефактов из OpenSpec
Статусы артефактов SHALL браться из `openspec status --change <name> --json`, в порядке зависимостей схемы change. Каждый артефакт MUST отображаться одним из статусов: готов, в работе (текущий артефакт сессии), ожидает подтверждения, отклонён, можно начинать (`ready`), заблокирован (`blocked`), пропущен (`skipped`). Изменения файлов change, сделанные вне сессии (редактором или другой сессией), MUST отражаться не позже чем через 2 секунды после изменения.

#### Scenario: Пользователь отредактировал файл вручную
- **WHEN** пользователь удалил `design.md` активного change в редакторе
- **THEN** не позже чем через 2 секунды `design` перестаёт отображаться готовым

#### Scenario: Схема без design
- **WHEN** схема активного change не содержит артефакта `design`
- **THEN** строка 2 показывает только артефакты этой схемы

### Requirement: Индикация текущей активности
Строка 2 SHALL показывать текущую активность с приоритетом: (1) ожидание подтверждения пользователя — с указанием артефакта или инструмента; (2) ожидание ответа MCP — с сервером, инструментом и секундами ожидания, обновляемыми каждую секунду; (3) артефакт в работе. Если ответа ждут несколько вызовов MCP, MUST показываться самый давний и количество остальных.

#### Scenario: Ожидание MCP
- **WHEN** вызов `mcp__context7__get-library-docs` ждёт ответа 8 секунд
- **THEN** строка 2 содержит `context7`, `get-library-docs` и `8s`, а через секунду — `9s`

#### Scenario: Несколько вызовов MCP
- **WHEN** ответа ждут три вызова MCP
- **THEN** строка 2 показывает самый давний вызов и пометку `+2`

#### Scenario: Ожидание подтверждения артефакта
- **WHEN** Qwen показал диалог подтверждения записи `design.md`, и одновременно ждёт ответа вызов MCP
- **THEN** строка 2 показывает ожидание подтверждения `design`, а не вызов MCP

### Requirement: Фазы без артефактов и apply
В фазе `explore` без активного change строка 2 SHALL показывать текущую активность или пометку об отсутствии активного change. В фазе `apply` строка 2 SHALL показывать прогресс задач активного change в виде `выполнено/всего` по чекбоксам `tasks.md`.

#### Scenario: Explore без change
- **WHEN** фаза сессии `explore`, активного change нет, вызовов MCP нет
- **THEN** строка 1 выделяет шаг `explore`, строка 2 сообщает, что активного change нет

#### Scenario: Прогресс apply
- **WHEN** фаза `apply`, в `tasks.md` активного change 12 задач, 5 отмечены выполненными
- **THEN** строка 2 показывает прогресс `5/12`

### Requirement: Вид вне OpenSpec-флоу
Если в сессии нет фазы OpenSpec-флоу, status line SHALL выводить ровно одно из двух. Либо вывод прежней команды status line пользователя, сохранённой при установке. Либо, если такой нет, одну компактную строку: имя проекта, git-ветка, модель и процент занятого контекста из данных, которые Qwen передаёт status line.

#### Scenario: Был пользовательский status line
- **WHEN** при установке был сохранён прежний status line пользователя, а в сессии нет OpenSpec-фазы
- **THEN** выводится то, что выводит прежняя команда

#### Scenario: Прежнего status line не было
- **WHEN** прежнего status line нет и в сессии нет OpenSpec-фазы
- **THEN** выводится одна строка с проектом, веткой, моделью и процентом контекста

### Requirement: Устойчивость и бюджет времени
Status line SHALL завершаться быстрее 1 секунды. Status line MUST NOT выводить сообщения об ошибках или трассировки стека. Если OpenSpec CLI недоступен или `openspec status` завершился ошибкой, строка 2 MUST показывать вместо статусов артефактов пометку «статус недоступен», а фаза, change и активность MUST показываться как обычно. Ответ `openspec status` MUST кешироваться и запрашиваться заново только при изменении файлов change или смене активного change.

#### Scenario: OpenSpec CLI не установлен
- **WHEN** команда `openspec` недоступна в окружении status line
- **THEN** строка 1 показывает фазу и change, строка 2 показывает «статус недоступен» и текущую активность

#### Scenario: Повторный рендер без изменений
- **WHEN** status line обновляется каждую секунду, а файлы активного change не менялись
- **THEN** `openspec status` повторно не запускается

### Requirement: Компактность и цвета
Каждая строка status line SHALL укладываться в ширину из переменной окружения `OPSX_UI_WIDTH` или ключа `width` в `.qwen/opsx-ui.json` проекта, по умолчанию 100 символов. При нехватке места первым MUST сокращаться имя change (с многоточием), затем подписи шагов флоу до первых букв. Цвета MUST задаваться только ANSI-кодами базовой палитры. При заданной переменной окружения `NO_COLOR` вывод MUST быть без цветовых кодов, а статусы MUST различаться символами, а не только цветом.

#### Scenario: Длинное имя change
- **WHEN** имя активного change длиннее, чем помещается в строку 1
- **THEN** имя сокращается с многоточием, и строка 1 не длиннее заданной ширины

#### Scenario: NO_COLOR
- **WHEN** задана переменная окружения `NO_COLOR`
- **THEN** вывод не содержит ANSI-кодов цвета, а готовые, текущие и заблокированные артефакты различаются символами
