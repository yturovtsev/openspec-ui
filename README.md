# qwen-opsx-ui — UI для OpenSpec-флоу в Qwen Code

Расширение Qwen Code показывает, что происходит в OpenSpec-флоу, прямо в текущей сессии:

```
opsx  explore › ● propose › apply › archive   add-auth
proposal ✓  specs ✓  design ◐  tasks ·   ⏳ context7›get-library-docs 8s
```

- **Строка 1** — шаг флоу (`/opsx-explore`, `/opsx-propose`, `/opsx-apply`, `/opsx-archive`; `update` и `sync` показываются пометкой у соседнего шага) и активный change.
- **Строка 2** — статусы артефактов из `openspec status` и что агент делает сейчас: какой артефакт пишет, ответа какого MCP-сервера ждёт и сколько секунд, ждёт ли вашего подтверждения. Во время `/opsx-apply` вместо артефактов показывается прогресс задач `5/12`.
- **Подтверждение артефактов** — каждая запись `proposal`/`specs`/`design`/`tasks` открывает нативный диалог Qwen с диффом, даже в режимах `auto-edit` и YOLO.
- В конце хода в ленте появляется сводка: `✓ opsx: design.md принят`.

Вне OpenSpec-флоу status line показывает компактную строку `проект · ⎇ ветка · модель · ctx 23%` или ваш прежний status line.

## Требования

- Qwen Code ≥ 0.25.2
- Node.js ≥ 20
- OpenSpec CLI ≥ 1.13 (`npm install -g @fission-ai/openspec`), в проекте выполнен `openspec init --tools qwen`

Сборка не нужна, зависимостей нет.

## Установка

1. Подключите расширение и перезапустите Qwen:

   ```bash
   qwen extensions link /path/to/openspec-ui      # локальная копия
   # или: qwen extensions install <git-url или путь>
   qwen extensions list                          # должно быть «OpenSpec UI»
   ```

2. Включите status line. Расширения Qwen не умеют прописывать его сами, поэтому это делает команда `setup` (запускать в корне проекта):

   ```bash
   node /path/to/openspec-ui/bin/opsx-ui.mjs setup          # в .qwen/settings.json проекта
   node /path/to/openspec-ui/bin/opsx-ui.mjs setup --user   # или в ~/.qwen/settings.json
   ```

   Если забудете, расширение один раз напомнит точной командой в конце первого ответа в OpenSpec-проекте.

   `setup`:
   - не трогает остальные настройки и ничего не меняет при повторном запуске;
   - не заменяет ваш собственный status line без `--force`; с `--force` сохраняет его и показывает вне OpenSpec-флоу;
   - не переписывает `settings.json` с комментариями — печатает фрагмент для ручной вставки;
   - предупреждает, если нет `openspec` в `PATH` или `.qwen/commands/opsx-*.md` (и подсказывает команду исправления, но не запускает её).

3. Перезапустите Qwen Code и запустите `/opsx-explore` или `/opsx-propose <что сделать>`.

## Символы

| | |
|---|---|
| `● propose` | текущий шаг флоу |
| `✓` | артефакт готов |
| `◐` | агент пишет этот артефакт |
| `⚠` | ждёт вашего подтверждения |
| `✗` | вы отклонили запись (до следующей принятой записи) |
| `○` | можно начинать |
| `·` | заблокирован зависимостями |
| `–` | пропущен схемой |
| `⏳ server›tool 8s +1` | самый давний ожидающий MCP-вызов и сколько ещё ждут |

## Подтверждение артефактов

Когда агент пишет или правит файл артефакта в `openspec/changes/<change>/` через `write_file`, `edit` или типовые shell-записи (`>`, `>>`, `tee`, `cp`, `mv`), Qwen показывает диалог «Да, разрешить один раз / Нет, предложить изменения». В диалоге указано, какой артефакт и какого change. Отказ (Esc) отменяет ход — напишите агенту, что поменять.

Не требуют подтверждения: служебные файлы (`.openspec.yaml`), архив (`openspec/changes/archive/`), вызовы самого `openspec`, а также отметка задач в `tasks.md` во время `/opsx-apply`.

## Настройки

| Переменная окружения | Ключ в `.qwen/opsx-ui.json` проекта | По умолчанию | |
|---|---|---|---|
| `OPSX_UI_APPROVAL` | `approval` | `all` | `all` — подтверждать создание и правку артефактов, `create` — только создание, `off` — без подтверждения. Неизвестное значение = `all` |
| `OPSX_UI_WIDTH` | `width` | `100` | ширина status line в символах (не меньше 40) |
| `OPSX_UI_HOME` | — | `~/.qwen/opsx-ui` | каталог журналов сессий и кеша |
| `NO_COLOR` | — | — | вывод без цветов (статусы различаются символами) |

Переменная окружения важнее файла. Пример `.qwen/opsx-ui.json`:

```json
{ "approval": "create", "width": 90 }
```

## Ограничения

- **Две строки.** Qwen Code 0.25 не даёт расширениям рисовать свои панели; UI — это status line (максимум 2 строки) и нативные диалоги. Пока открыт диалог подтверждения, футера не видно — нужное написано в самом диалоге.
- **Headless.** В `qwen -p …` диалог показать нельзя, поэтому запись артефакта при включённом подтверждении блокируется с подсказкой. Для таких запусков: `OPSX_UI_APPROVAL=off qwen -p …`.
- **Shell — best effort.** Запись артефакта через интерпретатор (`python -c …`, `node -e …`) или через переменные в путях не распознаётся. Контекст расширения (`QWEN.md`) просит агента писать артефакты только через `write_file`/`edit`.
- **Сбой хука = разрешение.** Если процесс хука упадёт, Qwen пропустит вызов без диалога. Путь гейта короткий и покрыт тестами; при внутренней ошибке для подходящего пути гейт всё равно спрашивает.
- **Сообщения в ленте — в конце хода.** Qwen выводит в ленту только сообщения `Stop`-хуков; если ход отменён отказом, сообщения нет, отказ виден как `✗`.
- Проверено на macOS с Qwen Code 0.25.2 и OpenSpec 1.13.0. Windows не проверялся.

## Приватность

Журналы сессий лежат в `~/.qwen/opsx-ui/sessions/` (вне репозитория) и содержат только фазу, имя change, идентификаторы артефактов, пути внутри `openspec/`, имена MCP-серверов/инструментов и время. Тексты промптов, содержимое файлов и ответы инструментов не сохраняются. Журналы старше 7 дней удаляются автоматически.

## Откат

```bash
node /path/to/openspec-ui/bin/opsx-ui.mjs setup --remove   # (--user для пользовательских настроек)
qwen extensions disable qwen-opsx-ui                        # или uninstall
rm -rf ~/.qwen/opsx-ui                                      # журналы и кеш, по желанию
```

## Разработка

```bash
npm test                    # unit и интеграционные тесты (node --test)
npm run e2e                 # сквозная проверка в настоящем Qwen (см. test/e2e/)
```

- `src/` — код расширения: `hooks/` (обработчики хуков и гейт), `state/` (журнал событий и редьюсер), `openspec/` (разбор shell-команд, статус change), `statusline/` (рендер), `setup.mjs`.
- `test/fixtures/payloads/` — payload хуков, снятые с Qwen Code 0.25.2; что в них выяснилось — `test/fixtures/README.md`.
- `test/harness/` — фейковая OpenAI-совместимая модель, отладочный хук и pty-драйвер TUI: ими снимаются фикстуры и гоняется сквозная проверка без настоящей модели.
